# TvBox For Emby

把 TVBox 的点播源接进 Emby：**搜索 → 试播 → 一键推送 → 在 Emby 里当普通影视看**。

一个 fnOS 应用（`tvboxhub.fpk`）+ 一个 Emby 插件（`TvBox.dll`），装完在浏览器里点点鼠标就能用，不用碰命令行。

> 当前版本 **v0.7.0**。
> 内部迭代期（0.5.x）的逐条开发记录保留在 [docs/CHANGELOG-internal.md](docs/CHANGELOG-internal.md)。

## v0.6.0 更新

302 播放模式 + 直链缓存自适应 + 同步体验大升级

- 🎬 **新增 strm 播放地址方式「302 重定向」**：strm 写本机地址、播放时实时解析回真 3xx —— 直链**永不过期**且 **NAS 不走流量**。ffmpeg 走新路由实测解码通过；老的 `/TvBox/Play?…` 地址继续可用，切换即时生效、无需重同步

- 📡 **同步进度 SSE 推送**：有变化才推（2 秒粒度）替代前端轮询；进度实时显示「处理中：《xxx》」和「已运行 m:ss」—— 同步再慢也能看出它在干活
- 📋 **新增「同步记录」面板**：最近 400 条条目级记录（写入 / 跳过 / 失败 / 换源），跳过带原因聚合（如「9 集全部不可用（原因：404×8）」），哪个站点在烂一眼可见
- 💾 **配置一键导出 / 导入**：54 项插件配置 + 站点名单 / VIP 关键字 / 解析接口一起备份回放，换机迁移不用重配
- 🐛 修 hub 配置白名单漏项：跨站换源两参数在界面上改会被静默忽略（一直跑默认值），连同直链探测 / 验活参数一起入白名单

## v0.5.0 更新

解析能力大修 + 内存减半 + 跨站换源

- ✨ 解析能力（照 TVBox 源码补齐三处差距）：
  - `playerContent` 的 `vipFlags` 以前传空列表 —— 有些 spider 因此只给低清线路甚至直接报"解析失败"（`半日99` 就是这条救活的）

- ⚡ 302 缓存：源站地址→最终地址缓存 10 分钟，两跳源同一集二播 **6.18s → 0.43s**；顺带修正播放列表相对分片路径按 302 后的地址解析（否则分片 404）
- 🔁 跨站换源：某条目在自己站点整条解不出时，自动去其它站搜同名影片（片名归一化 + 年份匹配），用能播的站写一份；写入不做任何清理
- 💾 常驻内存 **174MB → 88MB**（压测后 98MB）：堆参数收紧 + 线程池可回收 + 空闲 5 分钟清缓存并 GC
- 🛡 死链防护：解析失败不写库（校验开关不得为提速而关闭）+ 直链写盘前 `Range` 探测，首字节是 `<`（报错页/防盗页）自动退回代理
- ⚙️ 解析能力可在界面配置：VIP 关键字、解析接口模板（一行一个，`{url}` 会被替换）
- ⏱ 定时同步（默认 12 小时）、按站点建目录、同步名单可视化管理

## 为什么需要它

TVBox 生态里的源是「苹果 CMS」接口：能搜、能看详情，但没有媒体库，看完就忘，也没法在电视上按海报浏览。

这个项目做的事很简单：**把点播条目写成 `.strm` 文件**。Emby 把 `.strm` 当普通视频文件扫描入库，于是你得到海报墙、分类、继续观看、多端同步播放进度——而播放时真正拉流的还是源站。

多源的情况也照顾到了：每个站点单独一个目录，同一部片在几个站能看就存几份，谁挂了都不影响。

## 组成

| 组件 | 位置 | 说明 |
|---|---|---|
| **fnOS 应用** | `fpk-src/` | 生命周期脚本 `cmd/main`、Web UI、**内置裁剪版 JRE（x64 / arm64 各约 46 MB）**，装到 NAS 上开箱即用 |
| **spider-hub** | `spider-hub/` | Java 中转服务：跑 catvod spider、聚合搜索、代理播放、写 strm 的调度口 |
| **Emby 插件** | `TvBox.Plugin/` | 在 Emby 里提供搜索/推送/播放代理，负责补 Referer/UA 与 HLS 分片重写 |
| **spider 实验舱** | `spider-host/` | 验证「TVBox 的 dex 内 spider 能否直接在 JVM 跑」的探针工具，非运行时依赖 |

hub 与插件之间的调用很薄：插件调 hub 的 `/api/*`，hub 通过插件反向更新媒体库。

## 首次使用（5 步）

UI 的「使用说明」页有同样的清单，并且会**自动检测每一步是否完成**：

1. **填点播源** —— 配置页填 TVBox 配置地址（单仓 JSON / 多仓 urls / base64 / 本机绝对路径都行）
2. **选站点** —— 站点页勾选能用的源。建议先勾 3–5 个 ✅ 的试水
3. **设输出目录** —— 默认在 Emby 数据目录下的 `tvbox/`，也可指到自己的媒体盘
4. **装 Emby 插件** —— Emby 插件页一键安装，装完自动重启 Emby（有进度弹窗，恢复后自动关闭）
5. **跑同步** —— 同步页点开始；跑完在 Emby 里加媒体库并扫描

> 站点页的「**把可播站点全部加入同步**」只加**已确认可播**的站点。
> 「有列表」不等于「能播」——有些源的播放地址返回的是解析接口 JSON。没验证过的站会提示你先点「批量探测当前」。

## Emby 媒体库怎么加

同步产物按站点分目录：

```
<输出目录>/<站点名>/movies/<片名 (年份)>/<片名 (年份)>.strm
<输出目录>/<站点名>/tv/<剧名 (年份)>/Season 01/<剧名 (年份)> - S01E01 - <集名>.strm
```

所以媒体库也按站点建：

| 库类型 | 路径 |
|---|---|
| 电影 | `<输出目录>/<站点>/movies` |
| 电视剧 | `<输出目录>/<站点>/tv` |

站点多的话，也可以把 `<输出目录>/<站点>` 加成「**混合内容**」库，一个站点一个库。

命名遵循 Emby 规范：片名带 `(年份)`、集文件名 `剧名 - SxxEyy - 集名`、季目录 `Season NN`。集号优先从源站集名解析（`第12集` / `EP12` / `S02E05` / 纯数字），解析不到才按顺序补。

## 播放是怎么走通的

`.strm` 里写的不是源站直链，而是插件的代理地址：

```
http://<你的Emby>/TvBox/Stream?...   →  插件补 Referer / User-Agent  →  m3u8 分片地址重写  →  源站
```

这样防盗链的源也能播，同时播放进度、转码、多端同步都还是 Emby 原生的。

三种流模式（配置页「播放流模式」）：

| 模式 | 行为 | 适用 |
|---|---|---|
| `proxy`（默认） | 全部经 NAS 中转 | 需要补 Referer/UA、需要改写 HLS 分片 |
| `redirect` | 直接 302 到源站 | 省带宽；但防盗链的源会播不了 |
| `auto` | 按「允许 302 的域名」决定，m3u8 仍走代理 | 混合场景 |

概览页的「配置检测」会单独把 `redirect` 标红提醒——这是最容易配错、又最难自查的一项。

## 同步与清理的安全边界

- **只写不删**：正常情况下同步只写 `.strm` / `.nfo` / 海报
- **孤儿清理有清单**：「我们写过什么」记在 `<输出目录>/.tvbox-manifest.json`，只删清单里出现过、这次又不需要的文件；别人放进去的文件不碰
- **单次删除上限**：一次性要删超过 `MaxDeletePerRun`（默认 300）时直接停手并报错——防止命名规则一改就把整库删空
- **删除历史数据**（同步页）：先统计再确认，必须输入 `DELETE`；只进 `<站点>/movies`、`<站点>/tv` 两个子树，只删 `.strm .nfo .srt .ass .vtt .jpg .jpeg .png .webp .tbn`，不跟随也不删符号链接

## 网盘登录

侧边栏「**我的网盘**」。凭证本来就是这套 spider 的原生机制（所有网盘客户端都走
`Init.context().getFilesDir()/lzxw/` 读文件），本应用只是提供了界面 + 持久化 + 验活，
**没有改动一行 spider 代码**。

### 支持矩阵

| 网盘 | 扫码登录 | 粘贴凭证 | 凭证文件 |
|---|---|---|---|
| 115 | ✅ | ✅ | `115.txt` |
| 百度 | ✅ | ✅ | `baidu.txt` |
| 阿里云盘 | ✅ | ✅ | `aliyun`（无扩展名，JSON） |
| 夸克 | — | ✅ | `quark_cookie.txt` |
| UC | — | ✅ | `uc_cookie.txt` + `uc_token.txt` + `uc_machine_code.txt` |
| 天翼 | — | ✅ | `cloud189.txt` |
| 123 | — | ✅ | `cloud123.txt` |
| 迅雷 | — | ✅ | `xunlei.txt` |
| 光鸭 | — | ✅ | `guangya.txt` |

### 扫码登录的真实情况（别踩坑）

三家都能生成**官方**二维码，但「扫完能不能落地」取决于各家接口在这台机器上通不通：

- **115**：二维码来自 jar 自带的 `Qr115`。但 `get/status/` 带上 `time` 参数后会被
  风控黑洞（只带 `sign` 返 200，加 `time` 就 20s 无响应），所以扫完状态查不到 ——
  **115 建议直接用粘贴 cookie**。
- **百度**：`getqrcode` 的 `imgurl` 补 `https://` 就是 245×245 PNG；轮询 `unicast`
  是长轮询，没扫到时 30s 后返回 `{"errno":1}`（这是正常）。扫到后 `v` 里是 base64 的
  `bduss`。**这条路是完整的**。
- **阿里云盘**：`generate.do` 只返回 `codeContent`（官方内容），上游不给图片，
  所以二维码由前端 `qrcode-generator` **本地生成**（token 不出这台机器）。
  但 `query.do` 立刻回 `EXPIRED`（上游要求浏览器会话），**扫码落地走不通，请粘贴
  `refresh_token`**。

夸克 / UC / 天翼不给扫码按钮是故意的：夸克 uop 现在只回 token 不回 `qrcode_url`，
UC 的 `uop.uc.cn` 在本机解析不了，天翼 189 要 `date`+HMAC 签名 —— 与其给一个扫不动的码，
不如让人直接走粘贴。

### 凭证怎么存

```
${PKGVAR}/data/pan/            ← <PKGVAR> = /vol3/@appdata/tvboxhub
├── lzxw/                      ← spider 真正读的目录（0600，仅应用可读）
│   ├── 115.txt
│   ├── baidu.txt
│   └── aliyun
├── pan-vault.enc              ← AES-256-GCM 加密备份（密钥在 hub.json 的 panKey）
└── pan-vault.log              ← 备份操作记录
```

- 明文是**必须**的：spider 直接读文件，不解密。所以用 `0600` + 应用私有目录兜底。
- `pan-vault.enc` 用于重启恢复 / 换机迁移 / 连同备份带走；`panKey` 丢了就解不开。
- 「退出登录」把文件移进 `.trash/`，**不删**。

### 验活不是「文件写了就算成功」

保存后会立刻调一次该网盘的 `homeContent`，**只认「真的列出了条目」**：

> 调通了但一条都没列出来（分类 1）—— 凭证多半无效/已过期，或该网盘根目录是空的

为什么不用「分类数」判断：实测 115 用**假 cookie** 也能返回「分类 1 个」，
只看分类会把无效凭证误报成已登录。

### 启用之后

「启用网盘源并加入同步」= 打开 `allowNetdisk` + 把这 9 个网盘站加进 `syncSites`，
之后在「站点」页就能看到它们参与同步。

> **STRM 落盘由 Emby 插件负责**，hub 只提供 `/api/push`。
> 「只同步指定目录」需要在插件侧扩展，**当前版本未实现**。

hub 44 个路由（完整列表见 `spider-hub/src/hub/Hub.java`）：

| 分组 | 代表接口 |
|---|---|

| 内容 | `/api/home`、`/api/category`、`/api/detail`、`/api/search`、`/api/search-all`、`/api/probe`、`/api/netdisk` |
| 播放 | `/api/stream`、`/api/stream/seg`、`/api/play-resolve`、`/api/go` |

## 从源码构建

```bash
# 1) Emby 插件（首次会自动下载参考程序集 deb 并解包，不安装）
```

## 已知限制

- **dex 内的 spider 类**：TVBox 配置里一部分源把 spider 打成 Android dex，纯 JVM 跑不起来（实验数据见 `spider-host/`），这类源在站点页会显示不可用
- **需要登录的源**（B 站系等）要自备 cookie；**需要外部解析器**的源要自备解析接口模板
- 网盘类源（继承 `Pan` 基类）没有账号拿不到直链，默认在解析阶段排除
- 源站随时可能失效、改接口——这是第三方内容，不是本项目能修的

### v0.5.0 (2026-10-18)

解析能力大修 + 内存减半 + 跨站换源

- ✨ 解析能力（照 TVBox 源码补齐三处差距）：
  - `playerContent` 的 `vipFlags` 以前传空列表 —— 有些 spider 因此只给低清线路甚至直接报"解析失败"（`半日99` 就是这条救活的）
  - 单线路失败自动**按集名换其它线路**重试（不再一格失败整条放弃）
  - `parse=1` 的播放页新增**网页嗅探**：苹果CMS `player_aaaa` / 嵌套 iframe / 正文里的 m3u8·mp4·flv
- ⚡ 302 缓存：源站地址→最终地址缓存 10 分钟，两跳源同一集二播 **6.18s → 0.43s**；顺带修正播放列表相对分片路径按 302 后的地址解析（否则分片 404）
- 🔁 跨站换源：某条目在自己站点整条解不出时，自动去其它站搜同名影片（片名归一化 + 年份匹配），用能播的站写一份；写入不做任何清理
- 💾 常驻内存 **174MB → 88MB**（压测后 98MB）：堆参数收紧 + 线程池可回收 + 空闲 5 分钟清缓存并 GC
- 🛡 死链防护：解析失败不写库（校验开关不得为提速而关闭）+ 直链写盘前 `Range` 探测，首字节是 `<`（报错页/防盗页）自动退回代理
- ⚙️ 解析能力可在界面配置：VIP 关键字、解析接口模板（一行一个，`{url}` 会被替换）
- ⏱ 定时同步（默认 12 小时）、按站点建目录、同步名单可视化管理
